# МиСПрИС MVP

Минимальный MVP API для хранения категорий и листовых товарных таблиц в PostgreSQL.

## Что уже реализовано

- Поднятие API (`FastAPI`) и PostgreSQL через `docker compose`.
- Проверка/создание базы данных на старте приложения.
- Создание базовой таблицы категорий.
- Создание таблиц-подкатегорий через API с привязкой к родительской таблице.
- Создание листовых товарных таблиц (товары с `id`, `name`, `price`, `quantity`).
- Просмотр информации о БД, таблицах и срезов записей по диапазону.

## Запуск

```bash
docker compose up --build
```

Swagger:

- `http://localhost:8000/docs`

## Основные эндпоинты

### 1) Общая информация о БД

`GET /database/info`

Возвращает:
- текущую БД,
- базовую информацию по категориям,
- список всех таблиц (`all_tables`) с оценкой количества строк.

### 2) Создание базовых таблиц

`POST /database/tables/create`

Body:

```json
{
  "include_categories": true
}
```

### 3) Создание таблицы-подкатегории

`POST /database/subcategories`

Body:

```json
{
  "table_name": "amd",
  "parent_table_name": "processors"
}
```

Что делает:
1. Создает запись в родительской таблице.
2. Создает новую таблицу-подкатегорию.
3. Привязывает запись к подкатегории через `subcategory_id`.

### 4) Создание товара в листовой таблице

`POST /database/products`

Body:

```json
{
  "product_table_name": "amd_products",
  "category_table_name": "amd",
  "category_id": 1,
  "name": "AMD Ryzen 5 2600X",
  "price": 14990.0,
  "quantity": 7
}
```

### 5) Информация о конкретной таблице + просмотр записей

`GET /database/tables/{table_name}?start=0&end=10`

Параметры:
- `start` — начало диапазона (включительно), по умолчанию `0`
- `end` — конец диапазона (не включительно), по умолчанию `10`

Пример:

```bash
curl "http://localhost:8000/database/tables/amd_products?start=20&end=40"
```

## Текущие ограничения MVP

- Динамически создаваемые таблицы и связи пока без полноценной миграционной стратегии.
- Нет операций редактирования и удаления.
- Нет единого слоя бизнес-правил/валидации для сложных сценариев дерева.
- Нет визуального рендеринга дерева категорий.

## Roadmap

План на следующие этапы:

1. Редактирование записей.
2. Удаление записей и таблиц.
3. Обход всех таблиц как дерева.
4. Рендеринг дерева.
5. Балансировка дерева.

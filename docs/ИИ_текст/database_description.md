# 5. РАЗРАБОТКА БАЗЫ ДАННЫХ

Для хранения данных разрабатываемого классификатора была выбрана реляционная база данных PostgreSQL, так как она обеспечивает надежное хранение структурированной информации, поддерживает механизм внешних ключей и позволяет эффективно работать со связями между сущностями. Использование PostgreSQL целесообразно для поставленной задачи, поскольку разрабатываемая система должна хранить древовидную структуру категорий, сведения о конечных комплектующих и наборы их характеристик.

В рамках данной работы база данных используется как основа для хранения классификатора комплектующих ПК и серверов. В ней должны быть представлены категории, образующие иерархию, конкретные товары, относящиеся к выбранным категориям, спецификации, описывающие свойства этих товаров, а также перечисления, задающие допустимые значения для части характеристик. Таким образом, база данных должна обеспечивать не только хранение информации, но и возможность ее дальнейшего изменения посредством серверной части приложения.

Запуск базы данных осуществляется на локальном сервере PostgreSQL с использованием `docker compose`. При старте приложения автоматически выполняется создание базы данных, создание таблиц и подготовка корневой вершины классификатора. Такой подход позволяет обеспечить готовность рабочей среды без необходимости ручной инициализации структуры хранения, а также упрощает тестирование и демонстрацию функционирования системы.

Рассмотрим структуру разработанной базы данных. Для хранения информации используются основные таблицы: `categories`, `products`, `specifications`, `product_specifications`, `enumerations`, `enumeration_values`, `measurement_units`, `parameters`, `category_parameters` и `product_parameter_values`.

Таблица `categories` предназначена для хранения категорий классификатора. Каждая запись данной таблицы представляет отдельную вершину дерева. Поле `id` является первичным ключом и однозначно определяет категорию. Поле `name` содержит наименование категории. Поле `parent_id` является внешним ключом, указывающим на родительскую категорию. За счет этого поля реализуется иерархическая структура классификатора. Для корневой категории значение `parent_id` равно `null`.

Таблица `products` предназначена для хранения конечных элементов классификатора, то есть конкретных комплектующих. Каждая запись в данной таблице соответствует одному товару. Поле `id` является первичным ключом. Поле `name` хранит название товара. Поле `category_id` является внешним ключом и определяет, к какой категории относится данный товар. Дополнительно в таблице хранятся поля `price`, `quantity` и `description`, необходимые для описания стоимости, количества и краткой характеристики комплектующего.

Таблица `specifications` используется для хранения справочника характеристик. В отличие от модели, при которой характеристики дублируются отдельно для каждого товара, в данной работе используется переиспользуемый справочник уникальных спецификаций. Каждая запись содержит название характеристики и либо произвольное текстовое значение, либо ссылку на значение классификатора. Для характеристик с произвольным значением дополнительно может быть указана единица измерения через поле `unit_id` или частная единица измерения через поля `custom_unit_full_name` и `custom_unit_short_name`. Например, в таблице могут храниться записи `socket = AM4`, `tech_process = 3 нм`, а для характеристики `form_factor` вместо текстового значения может использоваться ссылка на запись из таблицы `enumeration_values`. Это позволяет избежать дублирования одних и тех же характеристик для разных товаров и при необходимости ограничивать часть значений заранее заданным списком.

Таблица `product_specifications` является связующей таблицей между товарами и характеристиками. Она необходима для реализации связи многие-ко-многим между сущностями `products` и `specifications`. Один товар может обладать несколькими характеристиками, а одна и та же характеристика может использоваться для нескольких товаров. Например, характеристика `socket = AM4` может относиться одновременно к нескольким процессорам и материнским платам. В таблице `product_specifications` хранятся два поля: `product_id` и `specification_id`, которые являются внешними ключами на таблицы `products` и `specifications` соответственно.

Таблица `enumerations` предназначена для хранения самих классификаторов. Каждая запись данной таблицы содержит название перечисления, его описание, а также временные отметки создания и последнего изменения. Примером такой записи является перечисление "Форматы материнских плат".

Таблица `enumeration_values` хранит элементы конкретных классификаторов. Каждая запись содержит ссылку `enum_id` на таблицу `enumerations`, тип элемента `item_type`, приоритет сортировки, описание и временные отметки. Если `item_type` имеет значение `value`, то запись является конечным значением и хранит текстовое поле `value`, например `ATX`, `microATX`, `Mini-ITX`. Если `item_type` имеет значение `enum`, то запись является ссылкой на другое перечисление и хранит поле `child_enum_id`. Благодаря этому одно перечисление может состоять как из конечных значений, так и из других перечислений без отдельной таблицы связей.

Таблица `measurement_units` предназначена для хранения справочника единиц измерения. Каждая запись содержит полное название единицы, сокращенное название и описание. Например, в таблице может храниться единица измерения с полным названием "нанометры" и сокращением "нм".

Таблица `parameters` предназначена для хранения метаданных параметров изделий. Каждая запись описывает не значение конкретного изделия, а сам параметр: системный код, полное название, описание, тип параметра, а также ссылку на единицу измерения или перечисление. Для числовых параметров типов `integer` и `real` может использоваться ссылка `unit_id` на таблицу `measurement_units`. Для параметров типа `enum` обязательно указывается ссылка `enum_id` на таблицу `enumerations`.

Таблица `category_parameters` хранит состав параметров конкретных классов изделий. Каждая запись связывает категорию из таблицы `categories` с параметром из таблицы `parameters`, задает порядок отображения, обязательность параметра, признак наследования и числовые ограничения `min_value` и `max_value`.

Таблица `product_parameter_values` хранит значения параметров конкретных изделий. Каждая запись связывает изделие из таблицы `products` с параметром из таблицы `parameters` и содержит одно из полей значения: `val_real`, `val_int`, `val_str`, `val_datetime` или `enum_value_id`. Такое разделение позволяет проверять тип значения параметра и сохранять данные в форме, соответствующей модели из задания.

Таким образом, структура базы данных позволяет хранить:

- иерархию категорий классификатора;
- конечные комплектующие, относящиеся к категориям;
- переиспользуемый справочник характеристик;
- перечисления, их конечные значения и вложенные перечисления;
- справочник единиц измерения;
- справочник параметров изделий;
- состав параметров классов изделий;
- значения параметров конкретных изделий;
- связи между товарами и их характеристиками.

Для обеспечения целостности данных в разработанной базе данных используются ограничения и проверки. Для таблицы `categories` обеспечивается уникальность названия категории в пределах одного родителя. Это исключает появление двух одинаковых категорий на одном уровне дерева. Для таблицы `products` обеспечивается уникальность названия товара в пределах одной категории. Для таблицы `enumerations` обеспечивается уникальность имени перечисления, а для таблицы `enumeration_values` - уникальность конечного значения или вложенного перечисления в пределах одного перечисления. Для таблицы `measurement_units` обеспечивается уникальность полного и сокращенного названия единицы измерения. Между таблицами установлены внешние ключи, что гарантирует корректность ссылок между категориями, товарами, спецификациями, значениями перечислений и единицами измерения.

Кроме того, на уровне прикладной логики реализованы дополнительные ограничения. Запрещается удаление категории, если в ней содержатся дочерние категории или конечные комплектующие. Запрещается перемещение категории в саму себя или в собственного потомка, поскольку это нарушило бы древовидную структуру классификатора. При добавлении спецификаций выполняется проверка существования аналогичной записи в справочнике, что позволяет повторно использовать уже созданные характеристики. Для спецификаций дополнительно контролируется правило, согласно которому характеристика может содержать либо произвольное поле `value`, либо ссылку `enum_value_id` на конечный элемент классификатора, но не оба поля одновременно. Единица измерения может быть задана либо ссылкой `unit_id` на справочник, либо частно через поля `custom_unit_full_name` и `custom_unit_short_name`. Для вложенных перечислений запрещено добавлять перечисление внутрь самого себя, а также создавать циклическую структуру вложенности. При записи значения параметра изделия проверяется, что параметр назначен категории изделия, тип значения соответствует типу параметра, а числовое значение находится в заданном диапазоне `min_value` и `max_value`.

Следовательно, разработанная база данных обеспечивает хранение иерархического классификатора комплектующих ПК и серверов, поддерживает повторное использование характеристик товаров, позволяет задавать фиксированные наборы допустимых значений через перечисления, поддерживает вложенность перечислений и создает основу для последующей работы серверной части приложения. Выбранная структура хранения является согласованной с проектной моделью системы и позволяет реализовать все основные операции над категориями, товарами, спецификациями и перечислениями.

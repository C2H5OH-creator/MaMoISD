# 5. РАЗРАБОТКА БАЗЫ ДАННЫХ

Для хранения данных разрабатываемого классификатора была выбрана реляционная база данных PostgreSQL, так как она обеспечивает надежное хранение структурированной информации, поддерживает механизм внешних ключей и позволяет эффективно работать со связями между сущностями. Использование PostgreSQL целесообразно для поставленной задачи, поскольку разрабатываемая система должна хранить древовидную структуру категорий, сведения о конечных комплектующих и наборы их характеристик.

В рамках данной работы база данных используется как основа для хранения классификатора комплектующих ПК и серверов. В ней должны быть представлены категории, образующие иерархию, конкретные товары, относящиеся к выбранным категориям, спецификации, описывающие свойства этих товаров, а также перечисления, задающие допустимые значения для части характеристик. Таким образом, база данных должна обеспечивать не только хранение информации, но и возможность ее дальнейшего изменения посредством серверной части приложения.

Запуск базы данных осуществляется на локальном сервере PostgreSQL с использованием `docker compose`. При старте приложения автоматически выполняется создание базы данных, создание таблиц и подготовка корневой вершины классификатора. Такой подход позволяет обеспечить готовность рабочей среды без необходимости ручной инициализации структуры хранения, а также упрощает тестирование и демонстрацию функционирования системы.

Рассмотрим структуру разработанной базы данных. Для хранения информации используются шесть основных таблиц: `categories`, `products`, `specifications`, `product_specifications`, `enumerations` и `enumeration_values`.

Таблица `categories` предназначена для хранения категорий классификатора. Каждая запись данной таблицы представляет отдельную вершину дерева. Поле `id` является первичным ключом и однозначно определяет категорию. Поле `name` содержит наименование категории. Поле `parent_id` является внешним ключом, указывающим на родительскую категорию. За счет этого поля реализуется иерархическая структура классификатора. Для корневой категории значение `parent_id` равно `null`.

Таблица `products` предназначена для хранения конечных элементов классификатора, то есть конкретных комплектующих. Каждая запись в данной таблице соответствует одному товару. Поле `id` является первичным ключом. Поле `name` хранит название товара. Поле `category_id` является внешним ключом и определяет, к какой категории относится данный товар. Дополнительно в таблице хранятся поля `price`, `quantity` и `description`, необходимые для описания стоимости, количества и краткой характеристики комплектующего.

Таблица `specifications` используется для хранения справочника характеристик. В отличие от модели, при которой характеристики дублируются отдельно для каждого товара, в данной работе используется переиспользуемый справочник уникальных спецификаций. Каждая запись содержит название характеристики и либо произвольное текстовое значение, либо ссылку на значение классификатора. Например, в таблице могут храниться записи `socket = AM4`, `capacity = 16GB`, а для характеристики `form_factor` вместо текстового значения может использоваться ссылка на запись из таблицы `enumeration_values`. Это позволяет избежать дублирования одних и тех же характеристик для разных товаров и при необходимости ограничивать часть значений заранее заданным списком.

Таблица `product_specifications` является связующей таблицей между товарами и характеристиками. Она необходима для реализации связи многие-ко-многим между сущностями `products` и `specifications`. Один товар может обладать несколькими характеристиками, а одна и та же характеристика может использоваться для нескольких товаров. Например, характеристика `socket = AM4` может относиться одновременно к нескольким процессорам и материнским платам. В таблице `product_specifications` хранятся два поля: `product_id` и `specification_id`, которые являются внешними ключами на таблицы `products` и `specifications` соответственно.

Таблица `enumerations` предназначена для хранения самих классификаторов. Каждая запись данной таблицы содержит название перечисления, его описание, а также временные отметки создания и последнего изменения. Примером такой записи является перечисление "Форматы материнских плат".

Таблица `enumeration_values` хранит значения конкретных классификаторов. Каждая запись содержит ссылку `enum_id` на таблицу `enumerations`, текстовое значение, приоритет сортировки, описание и временные отметки. Например, для перечисления "Форматы материнских плат" в этой таблице могут храниться значения `ATX`, `microATX`, `Mini-ITX`. Между таблицами `enumerations` и `enumeration_values` реализована связь один-ко-многим: одному перечислению соответствует набор значений.

Таким образом, структура базы данных позволяет хранить:

- иерархию категорий классификатора;
- конечные комплектующие, относящиеся к категориям;
- переиспользуемый справочник характеристик;
- перечисления и их значения;
- связи между товарами и их характеристиками.

Рассмотрим в таблице 1 основные функции базы данных, обеспечивающие создание структуры хранения, добавление, изменение, удаление и перемещение элементов классификатора, а также управление продуктами, спецификациями и перечислениями. Код реализованных функций приведен в приложении А.

**Таблица 1 - Функции базы данных**

| Название функции | Назначение | Вход | Выход |
| :--- | :--- | :--- | :--- |
| `create_tables` | Создание таблиц базы данных и подготовка структуры хранения | отсутствует | созданная схема БД |
| `ensure_root_category` | Создание или получение корневой категории классификатора | отсутствует | `id` корневой категории |
| `create_category` | Добавление новой вершины классификатора | `name` - название категории, `parent_id` - идентификатор родительской вершины | новый объект категории |
| `update_category` | Изменение названия существующей категории | `category_id`, `name` | обновленный объект категории |
| `move_category` | Перемещение категории в другую часть дерева | `category_id`, `new_parent_id` | обновленный объект категории |
| `delete_category` | Удаление категории при отсутствии дочерних категорий и товаров | `category_id` | подтверждение удаления |
| `create_product` | Добавление нового комплектующего в выбранную категорию | `category_id`, `name`, `price`, `quantity`, `description`, `specifications` | новый объект товара |
| `update_product` | Изменение данных существующего комплектующего | `product_id`, `name`, `price`, `quantity`, `description`, `specifications` | обновленный объект товара |
| `move_product` | Перемещение комплектующего в другую категорию | `product_id`, `new_category_id` | обновленный объект товара |

| `_get_or_create_canonical_specification` | Создание новой спецификации либо получение уже существующей | `name`, `value` или `name`, `enum_value_id` | объект спецификации |
| `list_specifications` | Получение полного справочника характеристик | отсутствует | список спецификаций |
| `create_enumeration` | Создание нового перечисления | `name`, `description` | объект перечисления |
| `list_enumerations` | Получение списка всех перечислений | отсутствует | список перечислений |
| `get_enumeration` | Получение одного перечисления | `enumeration_id` | объект перечисления |
| `update_enumeration` | Изменение названия и описания перечисления | `enumeration_id`, `name`, `description` | обновленный объект перечисления |
| `delete_enumeration` | Удаление перечисления вместе с его значениями | `enumeration_id` | подтверждение удаления |
| `list_enumeration_values` | Получение значений выбранного перечисления | `enum_id` | список значений перечисления |
| `create_enumeration_value` | Добавление нового значения в перечисление | `enum_id`, `value`, `priority`, `description` | объект значения перечисления |

| `update_enumeration_value` | Изменение значения, приоритета и описания элемента перечисления | `value_id`, `value`, `priority`, `description` | обновленный объект значения перечисления |
| `delete_enumeration_value` | Удаление значения перечисления | `value_id` | подтверждение удаления |
| `get_tree` | Построение полного дерева классификатора вместе с товарами и характеристиками | отсутствует | объект дерева классификатора |
| `get_database_summary` | Получение краткой информации о состоянии базы данных | отсутствует | статистическая информация по БД |

Для обеспечения целостности данных в разработанной базе данных используются ограничения и проверки. Для таблицы `categories` обеспечивается уникальность названия категории в пределах одного родителя. Это исключает появление двух одинаковых категорий на одном уровне дерева. Для таблицы `products` обеспечивается уникальность названия товара в пределах одной категории. Для таблицы `enumerations` обеспечивается уникальность имени перечисления, а для таблицы `enumeration_values` - уникальность значения в пределах одного перечисления. Между таблицами установлены внешние ключи, что гарантирует корректность ссылок между категориями, товарами, спецификациями и значениями перечислений.

Кроме того, на уровне прикладной логики реализованы дополнительные ограничения. Запрещается удаление категории, если в ней содержатся дочерние категории или конечные комплектующие. Запрещается перемещение категории в саму себя или в собственного потомка, поскольку это нарушило бы древовидную структуру классификатора. При добавлении спецификаций выполняется проверка существования аналогичной записи в справочнике, что позволяет повторно использовать уже созданные характеристики. Для спецификаций дополнительно контролируется правило, согласно которому характеристика может содержать либо произвольное поле `value`, либо ссылку `enum_value_id` на элемент классификатора, но не оба поля одновременно.

Следовательно, разработанная база данных обеспечивает хранение иерархического классификатора комплектующих ПК и серверов, поддерживает повторное использование характеристик товаров, позволяет задавать фиксированные наборы допустимых значений через перечисления и создает основу для последующей работы серверной части приложения. Выбранная структура хранения является согласованной с проектной моделью системы и позволяет реализовать все основные операции над категориями, товарами, спецификациями и перечислениями.
